# Automatic usage inventory: scheduled and background tasks, and the paid or quota-limited providers they touch

Prepared 2026-10-24 from this checkout (branch `universes-removal`). Method: read-only reading of code, SQL migrations and repo docs. No provider, live site, Vercel or Supabase dashboard was contacted, so nothing about live environment variables, live plans or live balances was observed; those are listed in section 4.

"Authorization" below means a written owner authorization that is visible in the repo. The repo can only show that a developer recorded one; it cannot prove the owner's own words.

---

## 1. Summary and verdicts

### Runs automatically and is authorized (as far as the repo shows)

1. **Monthly Events refresh** (`/api/cron/refresh-events-monthly`, two Vercel cron entries, 1st of each month, 12:00 and 13:00 UTC). Authorization recorded at `src/lib/events/monthlyRefreshPlan.ts:162-170` and `docs/design/events-monthly-refresh-proposal.md:3-5` (owner message of 2026-10-24: once a month, existing allowances, no top-ups, no paid overages, no repeated paid retries). It is on by default in code (`monthlyRefreshPlan.ts:168-170`), so it needs no environment variable to run. It has a once-a-month marker, an allowance check, fixed request counts and zero retries. The next automatic run is **2026-11-01** (12:00 UTC read-only check, 13:00 UTC refresh). No real paid run is recorded in the repo (`events-monthly-refresh-proposal.md`, "Verified with simulated services").

### Runs automatically with no established authorization, or no cap (needs the owner's eye)

These are event-driven (fire when a person does something) rather than clock-driven, but once the person acts, nothing further stops them:

2. **Direct-message push trigger**: every row inserted into `direct_messages` makes the database call `https://vltd.vercel.app/api/push/send-internal` (a Vercel function invocation) and then Web Push. No cap, no rate guard in the trigger, no authorization note found. The push services themselves are free; the cost is Vercel invocations and `pg_net`. (`supabase/migrations/20260821_push_secret_to_vault.sql:53`, `20260821_push_notifications.sql:70-71,89-91`)
3. **Club-post cross-posting triggers**: every `club_posts` insert can call Discord, Slack, Telegram directly from Postgres, and Reddit through `/api/clubs/notify-reddit` (a Vercel function plus Reddit OAuth). No cap, no rate guard, no authorization note found. Reddit is marked "genuinely UNVERIFIED end-to-end" in the route's own header. (`supabase/migrations/20260822_clubs_*_notify.sql`, `src/app/api/clubs/notify-reddit/route.ts:21-26`)
4. **Browser-tab polling** (runs while a signed-in or public tab is open, no person pressing a button): presence heartbeat every 60 s, DM unread count every 30 s, public-home launch counter every 30 s, vault sync page every 15 s, museum gallery refresh every 60 s. These spend Supabase requests and egress and, for the launch counter, a Vercel function call per tab per 30 s. No central cap. See table row A9.

### Exposure that is not automatic, but can spend money with no server-side cap (flagged for completeness)

5. **`/api/ai/analyze-item` and `/api/ai/analyze-coa` have no sign-in check, no quota check and no rate limit on the server.** The monthly AI-scan quota is enforced only in the browser, after the paid call has already returned (`src/app/vault/bulk/page.tsx:258-262`, `src/app/capture/page.tsx:687,708-709`, `src/components/ScanCapturePanel.tsx:656-664`). Anyone who can reach the URL can spend Anthropic credit directly. Output is capped (`max_tokens` 1024 and 512), input size is not capped in code. Single-item Add Item scan (`src/app/vault/add/page.tsx:1704`) and the certificate scan (`src/components/CoaScanButton.tsx:34`) are not metered by the quota at all.
6. **Auth-email routes** (`/api/auth/signup`, `/api/auth/password-reset`, `/api/auth/change-email`) have rate limits held in server memory only (`src/lib/email/signupRecovery.ts:86-98`), so they reset per serverless instance and per deploy. Emails go out through Supabase Auth.

### Not automatic

- `refresh-events` (daily) and `refresh-major-events` (weekly): not in `vercel.json`, and refuse unless `EVENTS_REFRESH_ENABLED` is exactly `"true"` (`src/lib/events/refreshSwitch.ts:11-13`, checked at `refresh-events/route.ts:47` and `refresh-major-events/route.ts:154`). Verified in code. Their retry memory tables do not exist (SQL file 8 withdrawn, `docs/audit-2026-10-18/repair-batch-18/CLOSEOUT.md:156-157`), so a hand-run would repeat paid searches if repeated.
- `/api/events/search` (SerpApi, visitor "Find events"): answers 503 before reading any key unless `EVENTS_LIVE_LOOKUP_ENABLED` is exactly `"true"` (`src/app/api/events/search/route.ts:105-110`; `refreshSwitch.ts:16-18`). No client code in `src/` calls it.
- All lookups in section 3 (PSA, UPC, Metron, Discogs, card lookups, AI scan, etc.): person-triggered.
- Stripe webhook: inbound only, no outbound spend.
- `scripts/` are manual. Only `postinstall` is wired to run automatically and it only copies a wasm file locally (`package.json` `postinstall`: `scripts/copy-zxing-wasm.js`). There is no prebuild, no GitHub workflow (`.github/workflows` does not exist), no `supabase/functions`, no `pg_cron`/`cron.schedule` anywhere in `supabase/`.

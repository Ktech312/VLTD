Wishlist layout: compact proposal

Proposal: awaiting your reviewNothing implemented or deployedMockup with fictional items

The Wishlist closeout left three usability problems: an opened item becomes a very long form on a phone, it stays open when you switch tabs, and Sort is off screen until you swipe the filter row. This page shows a fix, built only from components the app already has (WantRow, WantForm, ActionMenu, PillButton, Toggle), with populated examples. Every control below is a mock (clickable where it matters) so you can judge the layout before I touch the real page.

What changes, in plain words

TodayProposed
Opened item on a phoneOne long form: 14 fields plus category fields and notes, about 1,900 px tall.Five essentials first (Title, Category, Release date, Expected price, Quantity), then three labelled expanders: More product details, Category details, Notes and target price. Closed expanders show how many fields are filled. About … px tall with all expanders closed (measured on this mockup).
Switching tabsThe opened row stays open on the other tab.Switching tabs closes the row. Anything you typed and did not save is kept as a draft and the row shows an amber Unsaved edit tag. Open it again and the draft is restored.
SortOn a phone, Sort is at the far end of a sideways-scrolling filter row.Search and Sort share a fixed first row, always visible. The filter chips scroll on their own second row.
SaveSave changes is at the bottom of a long form.On a phone, a sticky bar keeps Save changes and Cancel in reach while you scroll inside the open row.
What does not changeFields, validation, blank stays unknown, manual entry for every category, Following rules, Pull List, the status control and menu on each row, Acquire. No new data is stored except the in-browser draft (session storage on this device).

Sort is a PillButton that opens an ActionMenu, the same pair the rows already use. It replaces the sort select at the end of the scrolling chip row.

Draft rules

  • Typing in an open row saves a draft in this browser session after each pause.
  • Switching tabs or opening another row closes this one and keeps the draft.
  • The closed row shows Unsaved edit. Opening it restores the draft, with a Discard draft link.
  • Save changes writes it for real and clears the draft. Cancel or Discard clears it.
  • Closing the browser tab drops drafts. Nothing unsaved is ever sent to your account.
